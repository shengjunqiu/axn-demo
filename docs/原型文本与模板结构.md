# 原型文本与模板结构

当前原型有两套文稿。主原型按文书 code 套红头和固定章节，正文随关联事件填充。V2 对话原型的页面文稿和安小能草稿是另一套固定章节，事件固定为遂川县明坑村山体滑坡。

章节在代码里都是「标题 + 正文」一对。主原型见 `src/seed/documentTemplates.ts`、`src/seed/resolveDocumentSections.ts`、`src/seed/mockDocuments.ts`。V2 见 `src/pages/v2/`。

## 正文从哪来

有三类实战画像时（青岭村山体滑坡、南湾堤段洪涝决口、石溪沟泥石流清障，各含待研判、力量投送中、救援中、待复盘），走 `buildDisasterSections`。没有画像时，用事件事实和演示资源走 `buildFromContext`，章节名不变，正文改成待核说明。

每篇红头共用这些版面字段：

| 字段 | 作用 |
| --- | --- |
| platform | 机关标志上方的平台名，多数文种为空；应急抢险要情为「中央企业应急救援综合平台」 |
| org | 机关标志，均为「中国安能建设集团有限公司」 |
| type | 红字文种，字间加空格 |
| showNumber / showTitle | 是否排期号、黑色标题。值班日报两项都否 |
| tail | 落款样式：`duty` 值班员、`brief` 要情、`report` 报告、`dynamics` 周动态 |

生成标题格式：`事件名 · 文种名（新生成）`。

## 主原型文书

### 按事件填充的过程公文

| code | 文种 | 红字 | 章节 |
| --- | --- | --- | --- |
| SITUATION_REPORT | 态势报告 | 灾 情 态 势 报 告 | 一、灾情概况；二、安全态势与发展关注；三、队伍与人员状态时效；四、安全场所与医疗资源核查 |
| RESOURCE_REPORT | 周边资源报告 | 周 边 资 源 分 析 报 告 | 一、抢险基本信息；二、安能队伍情况；三、其他央企队伍情况；四、安能装备情况；五、其他央企装备情况；六、重点防护目标情况；七、范围与数据核验 |
| RESCUE_PLAN | 现场处置行动方案 | 现 场 处 置 行 动 方 案 | 一、基本情况；二、任务受领与力量抽组；三、指挥机构；四、主要措施；五、风险困难与附件落款 |
| EMERGENCY_BRIEF | 应急抢险要情 | 应 急 抢 险 要 情 | 一、灾（险）情概述；二、投入力量及组织指挥；三、处置行动及战果；四、重点、难点及采取的措施；五、其他重要情况 |
| DUTY_DAILY | 值班日报 | 值 班 日 报 | 一、人员在位情况；二、应急救援情况；三、舆情上访情况；四、交接事项 |
| WORK_SUMMARY | 抢险总结 | 抢 险 总 结 | 一、基本情况；二、主要经验做法；三、深刻启示；四、下一步工作打算 |
| WORK_SUMMARY_REFLECT | 反思式总结（对话用，不单列文书库文种） | 同抢险总结 | 一、实际处置过程；二、处置方案；三、存在不足；四、下一步改进计划 |
| RESCUE_EVAL | 效果评估 | 救 援 效 果 评 估 | 一、当前处置情况；二、阶段性救援成效；三、评估结论；四、剩余风险与改进建议 |
| MEETING_MINUTES | 会议纪要 | 会 议 纪 要 | 有画像时：会议基本信息、会议议题、议定事项与责任分工、资料依据与待补事项。无画像时：一、会议议题；二、议定事项；三、落实安排 |
| KNOWLEDGE | 知识参考，不进文书库红头 | — | 预案；画像自带的战法小节；复核与适用边界 |

概况类章节共用同一组字段：事件名、灾种、地点、描述、影响范围、人员情况、阶段或处置状态、资料时间。队伍和装备写成「名称 / 数量 / 能力 / 状态」。

各章再填的内容：

- 态势报告：关键监测最新值、风险分布、约 100 公里检索圈层、医院候选。学校不写成安置场所。
- 周边资源报告：编写单位和统计截止待补；其他央企人装固定为「未取得」；防护目标待核；查询半径不沿用 300/10 公里样例。
- 处置方案：第四节内再分五段，依次是侦测依据、主战法、人装编组、安全撤离、综合保障。编组固定为侦测处置分队、专家技术组、主力作业梯队、综合保障组。
- 应急要情：候选力量、阶段进度、预案要点；报送和期号留空。
- 值班日报：在位和舆情两章是固定待核句；救援和交接章带入当前事件。
- 抢险总结：第一节附过程时间轴（序号、时间节点、环节、记录详情、状态）。
- 反思式总结：过程章附监测和力量；不足章要求单据或影像后才能写入正式总结。
- 效果评估：用完成数除以目标数得到模拟完成率。

### 对话里才会生成、章节不随事件画像展开的材料

| code | 文种 | 红字 | 章节 |
| --- | --- | --- | --- |
| GROUP_RECOMMENDATION | 智能编组推荐 | 编 组 推 荐 方 案 | 编组建议 |
| SURVEY_ANALYSIS | 现场勘察分析 | 勘 察 分 析 报 告 | 勘察资料 |
| RESOURCE_QUERY | 资源查询 | 资 源 查 询 结 果 | 一、检索条件；二、候选资源；三、核对说明 |
| RESOURCE_STATUS | 资源状态核对 | 资 源 状 态 核 对 | 一、待核清单；二、更新方式 |
| TRANSPORT_PLAN | 力量投送方案 | 力 量 投 送 方 案 | 投送依据 |

前三类在未生成前只有一句引导。资源查询和状态核对按当前事件资源列表填充。

智能体能力和文书的对应：勘察 → SURVEY_ANALYSIS；态势、态势报告 → SITUATION_REPORT；资源查询 → RESOURCE_QUERY；周边资源报告 → RESOURCE_REPORT；状态核对 → RESOURCE_STATUS；编组 → GROUP_RECOMMENDATION；方案、修订 → RESCUE_PLAN；偏差 → RESCUE_EVAL；总结 → WORK_SUMMARY。

### 文书库里写死的样稿

这些不随事件改写，直接放在 `DOCUMENT_CATEGORIES`。

日常工作总结（DAILY_WORK_SUMMARY，红字「工 作 总 结」）四章：一、工作范围；二、工作时间轴；三、亮点与依据；四、下一步工作。正文是「待填写 / 待补充」。

应急救援周工作动态（WEEKLY_DYNAMICS，红字「应 急 救 援 周 工 作 动 态」）三章：

- 一、上周工作完成情况：应急救援行动、应急能力建设、安全应急产业。
- 二、本周工作计划：同样三个分项。
- 附件：工程练兵情况统计表、安全应急产业营收情况统计表、本周中标项目汇总表。

预置两篇：防汛应急周工作动态、应急救援能力建设周工作动态。期号从〔2026〕第 13 期起。

其余会进文书库的预置题目：

| 文种 | 预置标题 |
| --- | --- |
| 值班日报 | 应急值守日报；夜间值守交接日报 |
| 应急抢险要情 | 险情处置要情；应急救援过程要情 |
| 会议纪要 | 应急协调会议纪要；值班值守工作部署会议纪要 |
| 抢险总结 | 阶段性抢险总结；应急值守保障工作总结 |

「重点河段险情处置要情」另附两张现场图：抢险机械进场、现场指挥组会商。样稿默认绑在事件 `evt-demo-001`。

## V2 对话原型

事件固定为「江西省吉安市遂川县高坪镇明坑村-山体滑坡灾情」。初报：9 月 5 日 6 时 40 分，8 栋房屋倒塌，10 人左右被困。

### 页面上的固定文稿

| 页面 | 标题 | 章节 |
| --- | --- | --- |
| 周边资源分析报告 | 遂川县 9 月 5 日周边资源分析报告 | 一、抢险基本信息；二、安能队伍情况（300 公里范围）；三、周边救援资源情况 |
| 资源调度建议方案 | 资源调度建议方案 | 一、灾情信息；二、力量编成建议；三、资源调度建议。第二节下有「力量编成建议表」 |
| 投送抽组方案 | 投送抽组方案 | 一、灾情信息；二、力量编成；三、投送安排；四、保障要求。第二节下有「力量编成表」 |
| 处置方案 | 救援处置方案 | 一、灾情基本情况；二、任务和救援目标；三、救援组织与力量编成；四、救援行动安排；五、安全与保障措施 |

周边资源页的队伍表头：所属工程局、队伍名称、队伍地址、所属梯队、队伍人数、队伍装备数、联系人、联系电话、距事发地距离。正文写 300 公里内 5 支队伍、171 人、装备 128 台/套；表内列出南昌队常备中队、永新项目部、梅江灌区项目部。

资源调度页编成表头：梯队、任务类型、人员数量、装备数量、主要能力。建议 125 人、72 台/套，分第一梯队、第二梯队、后备力量。

投送页编成表头：区分、队伍名称、抽组人数、抽组装备数、联系人、联系电话、距离、机动方式、预计行驶时间。合计 80 人、45 台/套：南昌队常备中队 52/42，指导组 28/3。

处置方案另有 3 条版本记录：任务与物资衔接版、搜救阶段调整版、初始行动框架版。均为草稿，未发布。

这一页的五章和主原型处置方案的五章不是同一套标题。

### 安小能草稿

对话结果不是红头公文，是卡片。卡片可以有标题、段落、表和分节。

| 入口 | 卡片 | 分节或表 |
| --- | --- | --- |
| 周边资源 | 周边安能队伍；距事发地最近的队伍 | 队伍、梯队、人数、装备、距离 |
| 资源调度 | 人员与装备需求；周边可调用力量；资源组合建议 | 资源调度建议；推荐依据与边界 |
| 处置方案生成 | 事件名 · 策略名 | 一、灾情与现场情况；二、救援目标与适用条件；三、力量编成与职责；四、阶段安排与任务衔接；五、安全与保障要求；六、调整、交接与结束条件 |
| 灾情动态 | 当前进展；灾情动态总结；救援方案更新建议；力量抽组影响 | 按所选报告归并 |
| 投送 | 投送安排；投送时效；投送抽组方案草稿 | 一、投送编成；二、机动与到场衔接；三、联络与安全保障 |
| 任务 | 任务分解草稿 / 责任组建议 / 分工表 | 任务、责任组、内容、时限、完成产物、前置依赖 |
| 任务文书 | 起草稿 / 完善草稿 / 简洁稿 | 一段正文，不另分章 |

页面上嵌套的手机态势页不是上述模板生成的，结构单独固定为：态势感知智能体卡片、事件要点、预警说明、建设材料，以及红头《灾情态势报告》和多源来源列表。事件用的是青岭村山体滑坡（模拟），与 V2 明坑村事件不是同一条。
