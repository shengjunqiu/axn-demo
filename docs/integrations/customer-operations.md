# 客户需求操作流程与接口约定

2026-10-11。当前用户确认尚无物联网/库存、通知、知识库接口。本文定义前端适配协议，未部署或声称存在后台服务。

## 页面入口

助手 → 更多动作 → 资源数据与预警 / 救援复盘与知识。已有资源预警通知、预警推送按钮转到同一处理面板。当前事件存在待处理通知时，助手显示监测通知数量。

资源流程：登记物资基线 → 绑定设备和事件 → 接收带来源、时间的记录 → 配置规则 → 自动检查 → 站内通知 → 已读/处理完成。设备、记录、库存、规则、通知、问题和发布回执保存在当前浏览器，可刷新恢复；演示数据重置同时清空这些数据。岗位是通知责任对象标签，本地原型没有多用户身份鉴权和跨设备共享。

出入库按单据编号去重。相同编号内容冲突、计量单位不匹配、负库存、迟到单据均拒绝并记录问题；批次中任一数据失败不提交其他数据。已复核标记不代表问题数据已修正，需更正原单据后重新导入。

监测按事件/指标检查每个设备最新采集时间的读数；过期或缺测不能判正常。巡检日志最多保留500条。相同规则、同一采集记录不重复通知；未处理预警更新内容后取消旧外部回执。浏览器定时器仅页面运行期间有效，后台持续调度、数据持久存储、推送投递与鉴权仍由正式服务承担。

## 接口与鉴权

填写同源地址或 HTTPS 地址。使用12秒超时、同源会话凭证；不在浏览器保存密钥。跨域服务需要配置 CORS；推荐由正式后端网关处理上游系统鉴权。自动同步至少5秒，可暂停。保存配置并不证明接口可用；只有实际同步成功更新数据。

### 物联网/库存数据 GET

先在面板登记物资基线和设备映射，再同步。接口应返回增量明细或可按编号幂等重放的明细，不能把库存快照误当入库数量。三数组均必填，允许空数组，每类最多10000条：

```json
{
  "readings": [{"id":"reading-001","deviceId":"sensor-001","assetId":"pump-001","eventId":"evt-demo-001","metric":"电量","value":15,"unit":"%","collectedAt":"2026-10-11T10:00:00+08:00","source":"物联网设备回执"}],
  "movements": [{"id":"stock-document-001","assetId":"pump-001","direction":"出库","quantity":1,"unit":"台","occurredAt":"2026-10-11T10:00:00+08:00","source":"仓储原始单据"}],
  "timeline": [{"id":"timeline-001","eventId":"evt-demo-001","stage":"到场","occurredAt":"2026-10-11T10:00:00+08:00","detail":"实际到场动作与回执内容","source":"现场到场回执"}]
}
```

时间必须包含日期和时区；时间轴环节仅接报、研判、出动、到场、处置、回撤、复盘。采集记录校验设备、物资、事件、指标、单位和时间。未匹配映射时拒绝导入，不自动猜测归属。

### 通知 POST

请求：`{idempotencyKey,eventId,target,text}`。幂等键由通知编号与采集记录编号组成；失败重试保持同一键。服务负责岗位解析、实际投递与幂等。

响应：`{"id":"真实接收回执编号","status":"accepted"}`。仅该有效回执使界面显示已确认接收，指接口/网关接收，不等于接收人已读或执行。站内已读、处理完成分别登记；无接口时外部发送按钮禁用。自动产生站内通知，外部通知由用户复核并点击发送，未实现无人审核的外部自动投递。

### 知识库发布 POST 与检索 GET

发布请求：`{idempotencyKey,eventId,title,body,tags}`；候选编号加更新时间作为版本幂等键。
响应：`{"id":"正式文档编号","indexed":true}`。`indexed:false` 显示已发布待索引，`true` 显示索引可用；未提供索引状态查询接口，暂不自动追踪后续索引完成。失败显示原因，可重试。正式发布回执独立于既有“已入库（模拟）”状态。

同一知识接口 `GET ?q=查询词` 返回：

```json
{"items":[{"id":"正式文档编号","title":"条目标题","body":"条目内容"}]}
```

未接入时检索禁用；空结果、失败和格式错误保留真实状态，不用本地模拟结果冒充正式库查询。

## 文书与复盘

会议纪要可导入 TXT/MD 或使用浏览器支持的语音识别输入，按关键词提炼议定、待核事项；用户确认内容可覆盖候选。日常总结按记录排序、提取成果和问题并引用原文行号。不处理录音文件转写，不调用大模型，麦克风识别依赖浏览器及其语音服务。

备选方案从十类灾种的现有本地预案抽取技术侧重点，展示适用条件、资源、风险、来源和限制。可补充预案名称、版本、条款及专业战法；无法匹配的事件保留组织方式参考并提示缺少专业依据，不套用其他灾种的工法。全部参考方案需专家审定，未计算成本、耗时或工程参数。

救援时间轴记录七环节实际节点和来源，缺少环节显示待补。登记后的记录优先用于后续生成的抢险总结时间轴；已生成文书不会自动改写。预案对照支持选择当前会话文书或输入总结，要求确认预案版本，逐条定位相关执行证据或缺证项。文字相关性不判定完成、合规或工程适用性。案例候选保留原始来源、预案版本、时间轴与对照内容；正式发布需要服务接入和内容复核。
