# 文本生成智能体文书清单

用途：供文本生成智能体开发团队确认文书种类与输出目录。范围为洪涝、泥石流、山体滑坡。

以下目录结合 V2 页面与助手生成模块整理；方案名称沿用招标对照名称。已实现的六个 V2 节点共用 `src/pages/v2/reportStructure.ts`，其余文书保留现有模板目录。二级标题是内容归类说明，不代表全部已有真实数据。一级标题使用“一、”，二级标题使用“（一）”，各一级章节内重新编号。

## 三、统一说明

- 同一材料的页面预览、聊天草稿和导出正文共用目录。标题中的花括号为生成时替换的变量；页面列表与文稿标题可按同一规则命名。值班日报正文保留现有红头版式，不强制新增黑色主标题。
- 灾情态势报告包含“标准化研判报告”别名；R03包含编组推荐、人装抽组和资源调度建议；R04包含力量投送、投送抽组；R05包含现场处置行动方案和救援处置方案，不重复开发同类模板。
- R06作为R05修订附件，不另列独立报告入口。R08采用统一总结目录，反思式总结内容归入过程、不足与改进相关章节。R13是否纳入本期交付仍待确认。
- 事件名称、统计截止时间、生成时间、版本、拟稿及审核信息作为文稿基本字段，不单独设置一级章节。正文缺少事实时标“待补充”；未核实结论不得写成已确认结果。
- 必要附表：R02资源明细；R03人装编成清单；R04投送编成与行程表；R05人装清单与现场资料；R06版本差异表；R07计划/实际/偏差表；R08过程时间轴与整改清单。R13保留工程练兵、安全应急产业营收、本周中标项目三张附件统计表。
- 多源摘要、资源查询、预警通知、知识问答等辅助卡片，以及项目验收、测试、安全测评报告不纳入本份文书目录。

依据：现有对照清单及 `src/seed/documentTemplates.ts`、`src/seed/mockDocuments.ts`、`src/pages/v2/pages/paperPages.tsx`。本次同步更新 V2 共用章节定义、助手生成内容及文书展示内容；不改写历史已保存文书。


## 四、V2 页面与助手展示模块对应（2026-10-15）

| V2 页面 | 统一材料名称 | 助手展示方式 | 章节与归并规则 |
| --- | --- | --- | --- |
| /v2/surroundings | 周边资源分析报告 | 文书预览、编辑、Word/PDF | R02 七章；其他央企及重点防护目标缺资料时写待补，不填零或认定安全 |
| /v2/assembly、/v2/resources | 力量编组与资源调度建议方案 | 对话内标准分节、字段表和人装清单；按需附件 | R03 三章；人装明细和职责归力量编成，出动条件与路线保障归调度建议 |
| /v2/plan | 工程救援处置方案 | 候选方向在对话中比较，确认后生成五章文书 | R05；补充内容归入第四、第五章，保留原始小标题与正文 |
| /v2/transport | 梯队投送方案 | 文书预览与编辑 | R04 四章；人数装备归力量编成，距离与时间口径及主备路线归投送安排，装载通信补给归保障要求 |
| /v2/dynamics | 灾情态势报告 | 依据动态反馈生成文书 | 一、事件与资料范围；二、动态反馈与依据；三、人员与救援进展研判；四、道路、坡体及力量变化；五、研判建议与待核项 |
| /v2/summary | 抢险任务总结报告 | 对话收集资料后生成总结文书 | R08 四章；过程、成效与投入归基本情况；问题线索归深刻启示；补录和改进归下一步工作，无经核实经验时保留待补 |
| 态势研判预警、预警推送、物资核验 | 危险提醒、通知草稿、核验结果 | 对话内 Notice、Section、KvTable、StatusPill、ChoiceChips | 不强行生成红头文书，不打开右侧业务流程面板 |

动态反馈形成的 V2 态势报告侧重历史变化，R01 通用模板侧重事件当前快照，两者材料名称相同、资料视角不同，不能把不同时点人装或累计救出人数相加。文书编辑器直接展示正文，不再额外展示章节目录按钮。
