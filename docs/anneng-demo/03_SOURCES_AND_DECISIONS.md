# 安小能 Demo：来源、差异与技术选型

版本：0.1  
整理日期：2026-09-28  
用途：区分原始材料、原型设计决策与外部技术资料。本文不是客户确认纪要，也不替代合同或验收大纲。

## 1. 阅读标识

- **[源]**：用户上传材料明确支持的需求。
- **[设]**：为本次客户演示提出的产品或工程设计，尚未得到客户确认。
- **[模拟]**：仅为展示交互而创建的数据、结果和状态，不是真实灾情、台账、法规或模型输出。
- **[待确认]**：原文存在差异，或需要客户、平台团队提供的未决信息。
- **[技]**：依据公开官方资料提出的技术选型，不是投标文件指定的技术栈。

本包的默认开发范围是产品文档中的 P0。P1 不是本次必须交付的范围，不能用 P1 扩展挤占 P0 的验证。

## 3. 原文差异与本次 Demo 处理

以下是明确的设计决策，不能对客户说成“原文已经统一确认”。

| 编号 | 原始材料中的差异或未决点 | 本次 Demo 的默认处理 [设] | 正式建设需要确认 |
|---|---|---|---|
| D-01 | S2 图 1 是三大专业智能体；S1 是六类智能体，资源管理与文书生成有单独职责 | 前台只展示业务任务，不展示 Agent 选择器。服务适配层按 S1 的专项职责命名；不搭建真实六 Agent 平台 | 最终智能体建设清单、任务归属与平台责任 |
| D-02 | S1 多处及末尾附录要求四类文书 ≤1 分钟；专项章节部分表述限定日报/要情，长会商又给出 ≤5 分钟，复盘长文待标定 | 全部保留在需求对照中；Mock 不测模型 SLA，不将两类口径擅自替换为最终承诺 | 文书类型、输入长度、计时起止、是否含 ASR/追问/排队 |
| D-03 | 前文给出打断 ≤500ms、同步 ≤3 秒；后文交互专项又写“试点标定” | Demo 只验 UI 可取消和本机状态一致，不宣称满足生产弱网或同步 SLA | 数值门槛、测试环境和责任方 |
| D-04 | L2 一致性为警告、L3 逻辑为建议；专项又要求无来源参数和未核实伤亡阻塞发布 | 保留普通 warn/info；无来源事实、冒充已调派、明确与事实矛盾的结论设 block，规则逐条列明 | 哪些可提示，哪些阻断，是否允许豁免 |

## 4. 推荐技术组合 [技]

默认新建项目：React 19.x + TypeScript + Vite + Ant Design 6.x + Ant Design X 2.x。文书编辑采用 Tiptap 的本地编辑基础能力；状态采用 Zustand；图表采用 ECharts；Word 导出采用 docx。地图 P0 是本地交互示意图，不接真实 GIS。

这些是推荐的版本线，不是已经安装验证过的精确依赖组合。T-001 必须实际查询版本、peerDependencies 与 Node engines 并生成唯一锁文件。核对日官方页面显示 Ant Design X 2.9.0、Ant Design 6.6.5、React 19.3；页面版本不等于所有配套包的版本，不能假设 x-markdown、x-sdk 都与 x 同号。

### W-01 Ant Design X

官方将其区分为 UI、Markdown 渲染、SDK 等能力；组件目录包括 Bubble、Conversations、Sender、Prompts、ThoughtChain 等。与本 Demo 的消息、会话、快捷任务和步骤展示相匹配。此处的“匹配”是项目选型判断，不是性能排名。

```text

https://x.ant.design/components/introduce-cn/
https://x.ant.design/components/bubble-cn/
https://x.ant.design/components/sender-cn/
https://x.ant.design/components/conversations-cn/
https://x.ant.design/components/prompts-cn/
https://x.ant.design/components/thought-chain-cn/
```

### W-02 Ant Design X 2.x 迁移与兼容

官方迁移指南建议配合 antd 6.x；2.1.0 起兼容多数 antd 5.x 组件，但可能有样式差异。旧版 useXAgent 已删除，运行时迁到 x-sdk；Bubble 自定义内容用 contentRender，Sender 的旧 actions 属性也有变化。必须按安装版本类型与示例写代码，不拼接 1.x/2.x 用法。P0 只使用 UI 和 Markdown，不引入 x-sdk、x-card、x-skill 的额外运行时依赖。

```text
https://x.ant.design/docs/react/migration-v2-cn/
https://ant.design/docs/react/introduce-cn/
https://react.dev/versions
https://vite.dev/guide/
```

### W-03 Tiptap

官方 React 安装指引使用 @tiptap/react、@tiptap/pm 与 @tiptap/starter-kit，可在 Vite 项目中使用。该选型负责编辑，不等于自带项目所需的校核、溯源与版本业务。不得默认为本项目引入需要付费或云服务的协同、版本比较、导出等功能；本包要求自建轻量快照差异。

```text
https://tiptap.dev/docs/editor/getting-started/install/react
```

### W-04 ECharts、Zustand 与导出

ECharts 官方支持按需导入，采用 core 路径时需明确注册渲染器。Zustand 提供 React 状态及持久化相关能力。docx 官方说明可在浏览器使用，并有 React 示例。window.print() 打开打印对话框，并不返回已保存的 PDF；应用无法据此断定用户完成保存。

```text
https://echarts.apache.org/handbook/en/basics/import/
https://zustand.docs.pmnd.rs/
https://docx.js.org/
https://raw.githubusercontent.com/dolanmiu/docx/master/README.md
https://developer.mozilla.org/en-US/docs/Web/API/Window/print
```

### W-05 没有选作默认方案的两个备选

assistant-ui 提供 React 聊天组件、运行时与后端适配；AI Elements 基于 shadcn/ui 并提供 AI SDK 相关集成。二者都可作为其他项目的候选。本 Demo 选择 Ant Design X 的原因是让业务表单、抽屉、校核面板和聊天保持一套 Ant Design 视觉及组件体系，不是认为其他框架能力不足。


## 5. 不应从来源推导出的结论

1. 原文中的指标是要求/承诺，不是本 Demo 已达到的实测结果。
2. 前端规则 Mock 并不证明具备真实 RAG、语音识别、专业研判或自动防幻觉能力。
3. 客户并未在本轮提供正式模板、真实接口、授权账号或品牌素材。
4. 本包中的机构、地名、队伍、知识条目、数值及案例均为虚构；不能对外说“来自真实业务系统”。
5. “引用 ID 有值”不足以证明内容正确；Demo 也要做值一致性与版本校验。
6. 文书模拟签发只更新本地状态，没有电子签章、审批效力或对外报送效果。
