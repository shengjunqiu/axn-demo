版本：0.1  
日期：2026-09-28  
状态：用于开发的原型范围建议，待产品经理/客户确认，不替代项目正式 PRD 或投标验收大纲。  
阅读对象：产品经理、Codex、前端开发、测试及演示人员。

## 0. 开发摘要

本次交付一个可以本地启动、真实点击、可反复演示的 React 高保真原型，不建设真实智能体平台。

**演示主题：安小能——从一句话到一份可核查的应急要情。**

**主线：选择事件 → 灾情摘要 → 查询资源并连续追问 → 查看上游处置建议 → 生成要情 → 补齐缺项 → 查看来源 → 修订与校核 → 模拟签发 → 导出与本地归档。**

主要界面只有两个：安小能工作台、文书工作台。数据溯源、历史版本和演示控制采用抽屉或弹层。打印预览是技术路由，不增加一级业务菜单。

默认技术组合：React + TypeScript + Vite + Ant Design + Ant Design X；文书编辑 Tiptap；图表 ECharts；状态 Zustand。具体版本及依据见 [技术与来源说明](03_SOURCES_AND_DECISIONS.md)。

**真正实现**：页面、状态变化、上下文引用、资源筛选排序、文书编辑、规则校核、版本快照、模拟角色门禁、本地存储、DOCX 文件生成、打印版式。

**明确模拟**：灾情/资源/监测/知识数据、AI 回复、任务编排服务、RAG、专业研判、语音转写、系统鉴权、签发及归档接口。

全局必须持续显示：`演示环境 · 模拟数据 · 非真实救援指令`。耗时展示为“本次演示耗时”，不能伪造“模型实测 6.4 秒”或“已达到标书指标”。

[源：S2-01、S2-04、S2-05] 用户围绕知识问答、文书生成、业务任务使用同一个入口，不需要选择 Agent。[源：S1-04、S1-10、S1-11] 安小能负责编排与呈现，文书智能体组织成文；二者不替代专项研判、原有权限与人工签发。

## 2. 产品目标与成功标准

| 目标 | 客户应看懂的内容 | Demo 可验证的结果 |
|---|---|---|
| 一个入口完成任务 | 不必切换多个 Agent 和业务系统 | 对话、地图、资源、建议和文书共享同一事件 |
| 任务不是普通问答 | 请求可以触发多步骤处理 | 任务卡有执行状态、阶段产物及可恢复错误 |
| 上下文连续 | “它们”“前两支”“按刚才建议”有明确对象 | 按会话中的有序实体集合处理，不猜第一条 |
| 文书依赖真实来源机制 | 字段、知识、语言组织各有边界 | 在模拟数据内做到字段可点击、值可核对、版本可追踪 |
| 人工控制关键结果 | 草稿不等于正式业务操作 | 缺项、过期校核及无权限阻断；模拟签发需确认 |
| 现场演示稳定 | 无外网、反复操作也能跑通 | 外网断开后本机服务可演示；一键重置；刷新恢复 |

[设] 不以真实模型准确率、真实弱网能力或投标 SLA 作为本 Demo 的通过标准。

## 3. 范围与优先级

### 3.1 P0：本次必须实现

| 范围 | 交付深度 |
|---|---|
| PC 安小能工作台 | 会话、事件上下文、快捷任务、可发送文字、可取消任务、工作区联动 |
| 灾情摘要 | 结构化要素、来源、待核实项、数据延迟状态 |
| 地图与图表 | 本地交互示意图、点选及列表联动、水位趋势；不是截图背景 |
| 资源查询 | 三支虚构队伍、两座仓库的本地筛选/排序；多轮引用；候选加入与移除 |
| 知识与建议 | 本地模拟知识引用、结构化上游建议展示；不生成真实工程指令 |
| 应急要情 | 模板填充、缺项追问、编辑、溯源、校核、版本、模拟签发、导出 |
| 值班日报 | 复用文书管线，支持班次统计、交接事项、编辑及导出 |
| 会议纪要/工作总结 | 只提供标明“模板预览”的章节示例，不伪装成可生成能力 |
| 演示控制 | 主线引导、重置、缺来源/服务超时注入、数据更新、演示角色切换 |
| 本地可靠性 | 状态持久化、错误恢复、中文输入、关键测试、演示说明 |

### 3.2 P1：明确不在默认开发范围

真实 ASR/TTS、大模型/RAG、真实 GIS 及路线算法、App/微信/数字人、真实 SSO/OA、真实派单和签收、原生 Word track changes、多人实时协作、一键 PDF 服务、完整四类生成、双方案专业对比、知识库管理、Skill 平台管理、真实离线包。

P0 的 PDF 为“打印 / 另存为 PDF”，不是一键下载。P0 的 DOCX 必须是真正的可编辑文件。P0 的应用内版本差异不等于 Word 原生修订。

### 3.3 禁止误做的范围

不要做登录注册、模型选择器、六个 Agent 的独立主页、空管理后台、付费编辑器服务、真实 API Key 配置或企业系统连接器。不要为了显得功能多而放无响应按钮。

## 4. 角色、上下文与权限

[源：S2-03] 原始材料覆盖指挥领导、值班员、调度人员、专家、现场负责人、复盘人员、管理员七类角色。

[设] 本次只展开两个“演示身份”，不是生产鉴权系统：

| 行为 | 演示值班员 | 演示指挥员 |
|---|---|---|
| 摘要、查询、知识、建议 | 可用 | 可用 |
| 生成、编辑、校核、保存草稿 | 可用 | 可用 |
| 提交待签发 | 可用 | 可用 |
| 模拟签发、退回修改 | 不可用 | 可用 |
| 导出本人可见且通过校核的文书 | 可用 | 可用 |
| 修改已签发版本 | 不可用 | 不可用；只能新建修订版 |

角色切换位于演示控制抽屉，切换后不丢文书。页面明确“演示身份”，不能声称已经验证后台权限安全。

顶栏上下文包含：当前事件、事件状态、当前模拟身份、数据时间、演训标识。选定建议显示其版本；未选定时不预填“已选定方案”。

一个事件可有多个会话，但一个会话只绑定一个事件。切换事件必须切换到该事件的会话，不能直接替换 eventId 后沿用上一事件的实体表。

## 5. 标准演示剧情 [设、模拟]

### 5.1 固定场景

事件：`演示区域 A · 清河段堤防险情`。所有名称均为虚构。默认演示时钟为 `2026-09-28 21:10 +08:00`，与用户电脑当前时间分开。

已确认响应等级为 IV 级；上游模拟建议为“建议升级 III 级，待人工确认”。当前险情状态为“持续处置中”，人员伤亡为“待核实”，不是 0。

主线演示中的资源仅加入候选，不实施派单。文书必须区分“拟预置力量”和“已调派力量”。

### 5.2 10～15 分钟演示脚本

| 步骤 | 演示操作 | 预期画面/行为 | 展示价值 |
|---|---|---|---|
| 1 | 进入主事件 | 已知事件上下文、推荐任务、空白对话欢迎状态 | 是业务工作台，不是空白聊天页 |
| 2 | 点击“灾情摘要” | 任务步骤依次变化；摘要、示意地图及趋势出现 | 信息整合与多模态 |
| 3 | 输入“查一下附近可调队伍” | 可用队伍列表与地图联动 | 业务数据查询 |
| 4 | 输入“它们谁最快到？” | 基于上一结果按 ETA 排序；显示同一数据时间 | 连续指代 |
| 5 | 输入“把前两支加入候选” | 候选栏显示 2 支、64 人、7 台挖掘机，均标“拟预置” | 上下文能产生业务结果 |
| 6 | 输入“结合当前险情给出初步处置建议” | 结构化建议、候选力量、风险和模拟知识引用 | 专项能力协同 |
| 7 | 点击“按此建议生成应急要情” | 文书任务检查字段，发现报送单位缺失并追问 | 不编造缺失字段 |
| 8 | 输入“报送单位是演示集团应急指挥中心”并确认 | 保存结构化人工补录记录，然后继续生成 | 人工补全与留痕 |
| 9 | 打开文书，点击水位数字及候选人数 | 来源抽屉展示快照与计算输入 | 可核查 |
| 10 | 将现状描述改为“险情已经得到有效控制”后重新校核 | 明确与事实不符的规则命中；可采用建议 | 校核是动态行为，不是固定绿勾 |
| 11 | 采用“现场正在持续处置，险情变化仍需跟踪核实”并重新校核 | 校核报告更新、问题消除；保存新版本 | 修订与再次校核 |
| 12 | 值班员提交 → 切换演示指挥员 → 模拟签发 | 确认当前版本；锁定；保存模拟签发记录 | 人工控制 |
| 13 | 导出 Word；打开打印预览 | 文件内容与选定版本一致，带演示标识 | 形成可交付结果 |
| 14 | 返回安小能，生成今日值班日报 | 复用事件/班次数据，可补交接事项并编辑 | 日常使用价值 |

步骤是引导，不是唯一可用的点击顺序。跳过查询直接生成要情时，系统也应能够补取已有事件事实；缺少建议不是必填错误，不能捏造方案或力量。

### 5.3 客户追问的演示回答边界

“这是真数据吗？”——页面必须能直接表明是模拟数据，本次展示的是后续接真实数据时的产品机制。

“能处理所有自然语言吗？”——这是有限话术覆盖的原型；支持的任务有快捷入口，陌生问题会说明未覆盖，不冒充通用大模型。

“已经自动调队伍了吗？”——没有；候选与正式调派严格分开，本次不接真实派单。

“已经达到 10 秒/1 分钟指标了吗？”——没有用 Mock 证明模型时效；生产验收需真实接口和约定测试条件。

## 6. 信息架构与页面布局

### 6.1 路由建议 [设]

| 路由 | 内容 | 规则 |
|---|---|---|
| `/workbench/:sessionId` | 安小能工作台 | 默认进入主事件会话；无效 ID 显示错误并提供回主场景 |
| `/documents/:documentId` | 文书工作台 | 保留 returnSessionId；从对话返回不重建会话 |
| `/documents/:documentId/print?revisionId=...` | 打印预览 | 只读、指定版本；权限/校核不满足时不渲染可打印正文 |
| `/` | 入口重定向 | 恢复最近合法会话；否则初始化演示 |

用两个工作台构成业务体验，不把所有抽屉都做成独立页面。

### 6.2 安小能工作台

桌面布局由“事件/会话导航 + 对话 + AI 工作区”构成。

- 顶栏 60～64px：产品名、事件标题、事件状态、演示身份、演示控制。
- 导航约 216px：当前事件与历史会话；“我的文书”作为侧栏抽屉入口，不新增大型菜单。
- 对话宽约 380～460px：消息、任务卡、快捷任务、输入框。
- 工作区占剩余宽度：`态势 / 资源 / 处置建议 / 文书`，每个 Tab 都有明确空状态。
- 来源、知识详情、历史版本：从右侧打开 Drawer。

对话中的卡片只展示要点与操作；完整地图、资源明细、建议放在工作区，避免同一长内容重复展示两次。

### 6.3 文书工作台

- 顶部：返回安小能、标题、模板、当前版本、生命周期状态、校核状态。
- 左侧约 180px：文书目录、章节定位。
- 中间：A4 视觉纸张；中文正文可编辑，事实标记可点击但不能任意改值。
- 右侧约 300～340px：`校核 / 来源 / 版本`；小屏时收进抽屉。
- 工具栏：保存版本、重新校核、提交、模拟签发、导出 Word、打印/另存为 PDF。

视图可采用连续纸张，不实现复杂分页编辑器；打印必须真实分页。页面应区分“本地自动保存”和“已保存版本”。

### 6.4 视觉与响应式 [设]

风格是清晰克制的业务 AI 工作台，不做大屏驾驶舱或普通后台首页。浅色底、深蓝主色、适当留白；红色仅用于阻断/危险，黄色用于待核实或延迟。

可采用主题基线：主色 `#155EEF`，正文 `#182230`，次要文字 `#667085`，页面背景 `#F5F7FB`，卡片 `#FFFFFF`，边框 `#E4E7EC`。这是演示设计建议，不是客户官方品牌色。

正文 14～16px，页面标题 22～26px，关键数据 20～28px，卡片圆角 10～12px，间距按 8px 节奏组织。不要全页大渐变、发光边框、满屏头像和重复标题。

主验收尺寸为 1440×900、1920×1080，兼容 1366×768。1280px 以下可折叠导航，1024px 以下用对话/工作区切换；移动端完整体验不在 P0。每个滚动区域明确高度，输入框和主要操作不得被挤出屏幕。

字体使用操作系统中文字体回退，不从互联网加载，不打包未授权字体。消息更新不强制把正在阅读历史的用户拉到底部；提供“有新消息”跳转按钮。

## 7. 功能需求

### FR-001 事件、会话与工作区上下文

[源：S1-02、S1-07；设] 展示当前事件；新增会话、切换历史、恢复会话；同一事件下可新建会话。会话记录自己的 lastResourceResultIds、candidateResourceIds、selectedProposalId、activeDocumentId、pendingClarification。

切换事件前若任务运行中，提示“切换将停止当前演示任务”；确认后取消并保留已完成内容。草稿先自动保存，不可丢失。严禁把事件 A 的水位、查询结果和文书上下文直接沿用到事件 B。日报的明确统计范围可以包含多个事件，但不能因此把两个事件的对话上下文混合。

### FR-002 AI 消息与输入

[源：S1-02、S2-05；设] 支持文字提交、Enter 发送、Shift+Enter 换行、中文输入法组合态保护；空白不发送；消息包含普通文字、任务、摘要、资源、知识、建议、缺项、文书、错误等类型。

使用 Ant Design X 的 Bubble.List、Sender、Conversations、Prompts 等组件，由业务状态驱动。流式演示从统一调度器增量追加，不能每个组件自行启动定时器。

保留停止与失败重试。复制答案是真复制；不做没有行为的赞踩。语音按钮若展示，命名“体验语音输入（模拟）”，点击打开预设口述文本，确认后作为正常消息提交；不申请麦克风权限，不标“识别成功”。

### FR-003 任务编排与过程呈现

[源：S1-04、S1-08；设] 一个请求可包含多个子任务；预取事实和检索知识可并行，建议依赖已有事实/资源，文书依赖字段补齐和选定建议。

任务状态：排队、执行中、待补充、部分完成、已完成、失败、已取消。步骤展示名称、输入范围摘要、执行状态、输出摘要、来源引用和本次演示耗时。

页面标题“执行过程与依据”，不展示内部模型私有推理。部分失败不清空成功结果；不能把失败子任务显示成已完成。单会话同一时刻最多运行一个顶层演示请求；新请求到来时选择“停止当前并执行新请求”或“暂不发送”。

### FR-004 灾情摘要

[源：S1-03] 要素包括发生时间、地点、灾种、影响、响应、待核实项和来源。

[设] 本次输出事实卡、进展概述、水位趋势入口、待核清单、更新时间。已确认 IV 级与升级建议 III 级分别显示，文书不能把后者写成已启动。

来源超时示例显示“水文源暂不可用，本次摘要未纳入最新水位”。缓存只能标“缓存/已过期”，不显示“实时”。缺失的伤亡不渲染 0，不写“无伤亡”。

### FR-005 态势示意图与图表

[源：S1-08；设] P0 使用本地 SVG 矢量示意图：河道、险情点、三支队伍、两座仓库和一处监测点。醒目注明“空间示意 · 非真实地图”。所有空间位置使用画布坐标，不伪装为真实经纬度。

点选显示资源详情；列表选择高亮同一 ID；候选队伍与普通点有视觉差异；基础图层显隐、缩放、复位可用。距离和 ETA 为模拟来源字段，不按 SVG 像素计算。

ECharts 绘制水位折线，资源栏可展示候选装备柱状图。标题、单位、时间、数据模式齐全；详情支持查看同源表格。数据来自同一对象，禁止写一份图表数组、另一份文字数值。

### FR-006 资源查询、排序与候选

[源：S1-03；设] 对本地资源数据执行名称/类型/可调状态筛选。默认仅返回可调队伍；可查看全部并说明忙碌队伍不可加入。

支持“它们谁最近/谁最快”“把前两支加入候选”“移除第二支”。指代依赖最近一次返回给用户的有序结果集合；不存在或有歧义时展示候选确认，不默认选第一支。

候选汇总必须实时计算：主线两支队伍共 64 人、7 台挖掘机。资源删除、重新排序和重查不自动调派。当前选择属于候选草案，正文必须使用“拟预置/候选”。

### FR-007 知识问答与引用

[源：S2-04、S1-03；设] 预置少量高频问答，如“要情需要哪些信息”“查看相关预案/类似案例”。回答展示本地模拟知识条目、版本、摘要和详情抽屉。

每条知识内容都注明“演示知识条目，不代表真实法规/预案”。不得虚构真实标准名称和条文编号来增强可信度。没有覆盖的问题说明“当前演示尚未配置该类问答”，推荐支持的任务，不生成任意答案。

### FR-008 处置建议展示

[源：S1-04、S1-10；设] 该能力是上游方案/态势输出的模拟结果，不由前端自己做工程研判。展示目标、建议方向、候选力量、待核实条件、风险与依据。

建议只用于演示，不给未经核实的工法参数、安全距离或救援指令。按钮“按此建议生成要情”记录 proposalId 与 version。未选定时可生成只含当前事实的要情；不为凑文书自动指定建议。

### FR-009 文书入口与模板

[源：S1-04、S1-05；设] 对话指令、快捷任务和建议卡均可触发同一个生成服务。P0 可选“应急要情”“值班日报”；会议纪要与工作总结只打开模板预览，按钮文案不能写成可用的“一键生成”。

要情默认当前事件；日报需要当前演示班次。弹层说明将使用的事件/班次、模板版本、资料时间和候选建议。支持取消，不因打开弹层就生成。

### FR-010 字段绑定与缺项补齐

[源：S1-11、S1-12；设] 生成前检查必填字段。默认主事件缺少 reportingUnit，任务进入 waiting_input；聊天里显示缺项卡并追问，文书可展示等待框架但不能标“已生成初稿”。

用户补“报送单位是演示集团应急指挥中心”后，展示结构化值确认；确认后写入本地模拟人工补录记录，包含操作者、录入时间、事实值、来源 ID，然后重新绑定。不能把聊天原文直接写入强制字段冒充系统来源。

同一待补项在原会话和文书工作台补充必须更新同一请求。刷新后仍能恢复待补状态。非关键且允许待核实的字段保留“待核实”；这不等于允许所有必填字段为空。

### FR-011 编辑器与来源追溯

[源：S1-11、S1-13；设] Tiptap 负责段落级富文本。功能限于正文编辑、标题/加粗/列表、撤销重做、章节定位，不做复杂排版桌面软件。

事实以带 factId 的受控内联节点呈现，不能直接把 42.30 改成 45.30 后继续保留原始来源。点击节点打开来源面板。需要更正事实时提示应修正源记录；本次仅允许演示控制的受控更新和明确的人工补录流程。

来源面板展示：当前正文使用值、来源系统（模拟）、原始记录/字段 ID、采集时间、版本、核实状态。计算值额外展示公式、输入事实和计算结果。引用指向**生成时快照**，不是总显示“最新值”。

叙述段可自由编辑；新增数字不能借同段已有引用自动洗成可信事实。全选删除或粘贴替换导致事实节点丢失时，校核必须发现。

### FR-012 规范与来源校核

[源：S1-05、S1-11、S1-13；设] 用可测试的本地规则模拟校核，不声称通用 AI 审核。规则见第 11 节。

每次报告绑定 documentId、revisionId/workingVersion、contentHash、contextSnapshotId、rulesetVersion。正文任何变更都让旧报告失效。用户点击“重新校核”后以当前快照计算，不直接显示固定“已通过”。

问题卡包含等级、问题说明、章节/字段、当前值、依据、建议和定位按钮。支持对特定叙述问题“一键采用建议”；仅改变目标段落，不能覆盖用户其他修改。采用建议后仍需重新校核。

### FR-013 版本、修订与数据更新

[源：S1-06、S1-13；设] 自动保存工作副本；“保存版本”创建不可变快照。初稿 v1.0，保存小改为 v1.1；已签发文书新增修订为 v2.0，并要求修订说明。

应用内版本对比至少包含章节文本、事实值、候选力量、来源快照版本。不同版本不能共用可变引用而被同步改写。

新监测数据到达后，草稿显示“来源已更新”，不得静默覆盖。点击“更新引用数据”生成新工作快照，保留未冲突叙述；涉及结论的变更需提示，再校核。已签发版本仍保持原数据，可导出旧版，但必须标明历史版本及数据截至时间。

### FR-014 提交、模拟签发与本地归档

[源：S1-11、S1-13；设] 值班员校核通过后提交待签发；指挥员可模拟签发或退回。签发弹层再次显示事件、文书、版本、来源时间、警告和演示标识。

提交或签发前重新检查最新工作副本及校核哈希、来源新鲜度、必填项和身份；不能只根据按钮禁用状态控制。未通过则说明阻断原因。

签发后保存签发人（演示）、实际点击时间、版本及内容哈希，冻结快照；记录“已模拟签发，未对外报送”。本地归档可在侧栏文书抽屉检索。双击只产生一次签发记录；刷新不重复签发。

### FR-015 Word 与 PDF 输出

[源：S1-13；设] Word 使用本地 docx 生成真正 DOCX：标题、段落、必要表格、来源附录和态势快照；内容由选定文书快照序列化。不能重生成另一份固定文本，不能把 HTML 改名为 .docx。

PDF P0 采用独立打印预览与浏览器打印/另存为 PDF。按钮必须如实命名；打开打印对话框不等于成功保存，取消打印不能显示“导出成功”。

仅通过当前校核的草稿或已模拟签发的锁定版本可导出；前者标“演示数据·草稿”，后者标“演示数据·模拟签发·非正式报送”。历史签发版按其签发快照导出，不因后续事实更新而改正文。

导出必须保留模拟标識，禁止真实印章/公章效果。字体可声明系统字体，不打包授权不明字体。态势图可转本地 PNG 插入 DOCX，但正文不能全部截图化；图题和数据时间仍是可选中文字。

### FR-016 演示引导、重置与持久化

[设] 演示控制提供：按步骤引导、正常/加速演示、切换演示角色、注入服务超时、注入缺来源、更新一条监测数据、重置当前场景。

引导只发送与用户手动操作相同的 action，不维护一份与真实页面脱离的播放状态。跳步时提示需要的前置条件；引导失败提供返回该步骤，不把步骤偷偷标成完成。

本地持久化会话、文书、版本、候选和待补状态；不持久化运行中的定时器/AbortController。刷新时 running 任务转为“上次演示已中断，可重试”，不能无限加载。

重置需要确认，清理本 Demo 命名空间、任务、文书、消息和临时 object URL，并恢复同一份种子数据；不使用 localStorage.clear() 删除其他应用数据。

### FR-017 异常与恢复

[源：S1-03、S1-04；设] 至少覆盖：未知问题、无结果、指代不明、缺必填、缺来源、服务超时、任务取消、源数据更新、校核过期、无签发权限、导出失败、存储不可用。

错误必须说明发生在什么步骤、哪些结果仍可用、下一步如何做。重试是重试失败步骤/当前请求的新 attempt，不重复发送用户消息、不重复生成签发/归档副作用。

未知问题示例：`当前原型尚未覆盖此类请求。可体验：灾情摘要、资源查询、应急要情、值班日报。` 不显示误导性的模型“思考中”然后输出无关固定答案。

### FR-018 本地性、隐私与可访问性

[设] 安装依赖后，运行时不得请求外部地图、字体、模型、遥测或 CDN。应用通过本地服务运行，不要求 file:// 双击 HTML。图片/图标本地打包，无远程头像。

不录音、不读取真实定位、不采集真实账号数据。输入中出现脚本或 HTML 按普通文本或严格白名单处理，禁止 eval 和直接运行 Markdown 中代码。

关键操作具备可读名称、可见焦点、键盘操作与可理解状态，不只靠颜色；图表提供文字/表格摘要。抽屉关闭恢复焦点。减少动态效果偏好下减弱打字和过渡动画。

### 9.4 内容模型与引用

文书内容不能只有一整段 HTML。建议采用章节/段落树，内联内容区分：

```ts
type InlineRun =
  | { type: 'text'; text: string }
  | { type: 'fact'; factId: string; format?: string }
  | { type: 'knowledge'; chunkId: string; label: string };

interface DocumentParagraph {
  id: string;
  role: 'fact' | 'narrative' | 'reference';
  runs: InlineRun[];
}
```

Tiptap 是交互层；通过 serializer 与领域模型转换。受控 fact 节点从文书自己的 sourceSnapshot 取值。知识片段不能作为当前灾情人数/库存的事实替代品。

哈希覆盖正文、事实取值、引用、候选、模板版本和来源快照 ID；不纳入动画进度等 UI 字段。校核与签发使用同一 canonical serialization，不能各算各的。

## 10. 状态机与不变量

### 10.1 任务状态

`queued → running → succeeded / partial / waiting_input / failed / cancelled`

waiting_input 补齐后可回 running；取消后不得再提交该 attempt 的晚到结果。失败重试创建新 attemptId。每个任务事件都携带 sessionId、eventId、taskId 和 attemptId。

### 10.2 文书状态分维度

不要把生成、校核、审批、来源新鲜度混成一个枚举。

| 维度 | 状态 |
|---|---|
| 生成任务 | queued / running / waiting_input / succeeded / failed / cancelled |
| 生命周期 | draft / submitted / signed / archived |
| 校核 | not_run / running / passed / failed / stale |
| 数据新鲜度 | current / stale |

退回：submitted → draft。已签发修改：创建新的 draft 和新版本线，旧 signed 快照不动。archived 可查看和按锁定快照导出，不原地编辑。

### 10.3 签发/导出不变量

草稿提交或模拟签发必须同时满足：字段齐全；所有必需事实可解析且值一致；校核通过且 hash 与当前内容一致；草稿来源 current；没有 block 问题；warning 已按设计处理；用户有对应演示权限。

已签发版本导出以其签发时内容、校核报告和来源快照为准；后续源更新不能篡改，也不能误要求把历史稿“更新成最新”。

同一模拟签发动作以 `documentId + revisionId + action` 去重。候选加入、文书导出都不能修改资源为“已出动”。

## 11. 可执行的 Demo 校核规则 [设]

规则按源材料理念实现，但以下 ID、具体条件和分级是本轮设计。它们不是完整的生产规则库。

| 规则 | 条件 | 结果/处理 |
|---|---|---|
| R-001 必填缺失 | 模板 required_fields 中存在真正缺失值；允许 pending 的字段另行配置 | block；显示缺项，返回补齐流程 |
| R-002 引用缺失 | fact 节点所引用事实/源字段不存在、被删除或无来源 | block；定位字段，禁止提交/签发/导出 |
| R-003 值与来源不一致 | 受控节点值/派生值与快照原值或计算结果不一致 | block；显示原值和当前值 |
| R-004 未核实伤亡 | casualty=pending，但正文写“无人员伤亡”或确定伤亡数 | block；建议“人员伤亡情况待核实” |
| R-005 无依据控制结论 | controlStatus=ongoing，但正文含“险情已经得到有效控制”等预置明确矛盾表述 | block；给出持续处置的替代表述 |
| R-006 候选冒充已调派 | 无 confirmedDeployment，却把候选写为“已调派/已出动” | block；建议“拟预置”，不更新台账 |
| R-007 草稿来源过期 | 当前可用源版本高于 draft 的 contextSnapshot | block；先显式刷新引用再校核 |
| R-008 校核报告过期 | 当前 contentHash 不等于报告 contentHash | block；要求重新校核 |
| R-009 引用跨事件 | 引用了不属于当前事件/授权资源快照的事实 | block；返回引用异常，不暴露其他事件正文 |
| R-010 新增无来源数字 | narrative 段新增数字表达且未结构化绑定到事实；单有其他引用不豁免 | block；提示改用事实引用；规则覆盖阿拉伯及常用中文数词 |
| R-011 演示标识缺失 | 导出模型缺少演训/非正式报送说明 | block；自动恢复不可删除标识并重算 |
| R-012 普通表述建议 | 预置非事实性冗长表述或交接事项过短 | warning/info；用户可修订或说明处理 |

R-010 是有限词法检查，不假装具备生产 NER/事实核验。仅作用于叙述正文，不把目录序号、模板版本、页码错误计为业务事实；也不把“进一步”“下一步”“统一”等词中的单字误判为数量。数量表达和误判豁免必须有正反例测试，不承诺覆盖任意语言；精确范围由单元测试固定。

“采用建议”修改目标段落后，旧校核状态变 stale；不能同时偷偷标通过。最终 issue 数量和来源覆盖数由真实模型计算，不写死“12/12”。

## 12. Mock 服务与数据流 [设]

UI → action / command → application service → provider → 领域对象 → store → 页面。禁止在点击事件里按第几步直接替换整屏固定 JSX。

建议服务：

```ts
interface AssistantProvider {
  run(request: AssistantRequest, signal: AbortSignal): AsyncIterable<TaskEvent>;
}
```

`AssistantRequest` 包含请求 ID、sessionId、eventId、用户输入或明确 commandId、上下文引用和演示场景配置。`TaskEvent` 是有限的判别联合：step_started、step_completed、text_delta、artifact、clarification_required、failed、completed。

摘要、资源、知识、建议、文书分别用适配器组织；所有结果是可替换的结构化对象。仅 Mock 实现，无真实 HTTP 服务和真实 Function Calling。以后真实接入替换 provider，不能把 UI 和脚本强耦合。

### 12.2 异步与取消

统一使用可中止调度器，测试可注入 Clock/ID factory。React StrictMode 不得导致重复执行。task 完成/取消/失败、事件切换、组件卸载与重置均清理订阅及延时。

写回前二次验证 taskId、attemptId、sessionId、eventId 是否仍有效；只 AbortController 不够，晚到事件也要被 store 拒绝。重试/重新生成都有新的 attempt，防止旧消息覆盖新结果。

## 13. 非功能要求与交付标准

开发目标为可演示而非生产性能承诺。动画总等待尽量控制在数秒；用户可以加速，但显示计时只能记录真实模拟执行耗时。若 UI 展示标书目标，明确写“建设目标，非本次模型实测”。

构建无 TypeScript 错误，无新增 ESLint 错误；关键动作无未处理 Promise rejection。必要异常也不能让整个页面崩溃，提供局部 ErrorBoundary。

本地存储加 schemaVersion；损坏数据支持“备份并重置当前演示”，不得静默白屏。避免在每个打字 token 时序列化整个大状态；对文本和草稿保存做节流，失焦/路由切换前补存。

测试包括领域单元测试、组件交互测试、浏览器主线及异常回归；最终截图覆盖两个工作台、来源、校核错误和签发只读状态。不能只给首页截图和一个 build 通过声明。

## 15. 给 Codex 的执行原则

按 [02_DEVELOPMENT_TASKS.md](02_DEVELOPMENT_TASKS.md) 的阶段交付。先建立数据模型、状态和一个可观察的界面闭环，再补文书与异常；不是先把所有页面静态画完才连接交互。

工程完成的判定是：客户能够沿主线反复操作，同时在中途追问、取消、修改内容、刷新后恢复；不是组件已经摆满页面。

本次不要求真实后端，但所有核心状态必须真的计算、保存、校验和联动。模拟模型不等于可以模拟保存、模拟下载或模拟校核结果。
